# Vacancy Bot — вакансии из «Работа в России» → Telegram

Ежедневно забирает вакансии выбранных компаний через официальный открытый API
«Работа в России» (opendata.trudvsem.ru), проставляет теги и постит в
Telegram-канал. Работает полностью на GitHub Actions — свой сервер не нужен.

## Почему через этот API, а не парсинг сайтов

- Официальный источник Роструда: по закону работодатели обязаны регистрировать
  каждую вакансию в госслужбе занятости — значит, данные полные и достоверные.
- Не нужен headless-браузер, антибот-обход, разбор разной вёрстки под каждую
  компанию — единый JSON-формат для всех.
- LLM для извлечения полей больше не обязателен: API уже отдаёт структурированные
  данные (должность, зарплата, регион, требования, график). Gemini используется
  только опционально — для 1-2 доп. тегов по смыслу описания.

## Быстрый старт

### 1. Создайте репозиторий на GitHub и залейте эти файлы

```bash
git init
git add .
git commit -m "init"
git remote add origin <ваш-репозиторий>
git push -u origin main
```

### 2. Получите ключи (только Telegram обязателен)

- **Telegram Bot Token**: создайте бота через [@BotFather](https://t.me/BotFather)
- **Telegram Chat ID**: добавьте бота в канал как администратора, узнайте
  chat_id канала (например через @userinfobot)
- **Gemini API key** (опционально, для доп. тегов): https://aistudio.google.com/apikey —
  бесплатный лимит с большим запасом. Если не указать — бот всё равно работает,
  просто без семантических тегов сверх базовых.

### 3. Добавьте секреты в GitHub

**Settings → Secrets and variables → Actions → New repository secret**

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`
- `GEMINI_API_KEY` (необязательно)

### 4. Заполните список компаний

Отредактируйте `companies.yaml` — впишите реальные ИНН компаний:

```yaml
- name: "Моя компания"
  id_type: "inn"
  id: "1234567890"
```

Найти ИНН можно на nalog.ru («Прозрачный бизнес») или просто поиском в интернете.

### 5. Настройте шаблон поста

Отредактируйте `template.md` (синтаксис Jinja2). Доступные переменные:
`title`, `company`, `region`, `remote`, `employment_label`, `experience_label`,
`salary_text`, `tags`, `url`.

### 6. Запустите вручную для проверки

Вкладка **Actions → Daily vacancy fetch & post → Run workflow**.

Далее крон будет запускать пайплайн автоматически каждый день в 08:00 UTC
(поменяйте `cron` в `.github/workflows/daily.yml`, если нужно другое время).

## Как добавить новую компанию

Допишите блок в `companies.yaml` с её ИНН и закоммитьте — при следующем запуске
её вакансии уже будут забираться. Редеплой не нужен.

## Как это работает

1. Крон запускает `main.py`.
2. Для каждой компании из `companies.yaml` — запрос к
   `https://opendata.trudvsem.ru/api/v1/vacancies/company/inn/{инн}` с пагинацией.
3. Из JSON-ответа напрямую (без LLM) извлекаются: должность, регион, зарплата,
   график, требуемый опыт — и на их основе строятся детерминированные теги
   (`#удаленка`, `#безопыта`, `#вахта`, регион и т.д.).
4. Если задан `GEMINI_API_KEY` — дополнительно запрашивается 0-2 семантических
   тега из текста обязанностей/требований (только из заданного белого списка).
5. Рендерится пост по `template.md` и отправляется в Telegram.
6. ID уже опубликованных вакансий сохраняются в `state.json`, который коммитится
   обратно в репозиторий — так дедупликация переживает между запусками.

## Структура проекта

```
.
├── .github/workflows/daily.yml   # крон-задача
├── companies.yaml                # список компаний (ИНН/ОГРН)
├── template.md                   # шаблон поста для Telegram
├── main.py                       # вся логика пайплайна
├── requirements.txt
└── state.json                    # какие вакансии уже опубликованы (обновляется автоматически)
```

## Ограничения API и что учесть

- Пагинация — не более 100 записей за раз (в коде уже реализован цикл по offset).
- Общий лимит выдачи — не более 10 000 записей на запрос (актуально только для
  очень крупных запросов по всей стране/региону, для одной компании не критично).
- В API нет явного поля "удалённая работа" — тег `#удаленка` определяется
  эвристикой по ключевым словам в графике/названии. Если для вашей отрасли
  эвристика промахивается — донастройте `guess_remote()` в `main.py`.
- Регион в API — это область/республика/край, а не конкретный город. Если
  нужен город — его можно поискать в поле `addresses`, но эти данные не всегда
  заполнены работодателем.
